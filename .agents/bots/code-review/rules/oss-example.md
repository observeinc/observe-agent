# OSS collector examples must match the agent

`examples/oss-collector/` contains OpenTelemetry Collector configurations for customers who run a plain `otelcol-contrib` collector instead of the Observe Agent. The Observe documentation links to them. They must process data the same way the agent does.

## When this rule applies

Check this rule when a pull request changes any of:

- `internal/connections/bundledconfig/**` (the agent's bundled collector configuration)
- `internal/config/**` defaults that change the rendered collector configuration, such as RED metrics dimensions
- `examples/oss-collector/**`
- `scripts/generate_oss_examples/**`
- the OpenTelemetry Collector version in `go.mod`

## What to check

1. **The examples are regenerated.** `examples/oss-collector/host/collector.yaml` is generated by `make generate-oss-examples` from `examples/oss-collector/host/agent-reference-config.yaml`. If the pull request changes the bundled configuration in a way that affects forwarding, RED metrics, resource detection, or host metrics, the generated example must change in the same pull request. Flag hand edits to `collector.yaml` that aren't produced by the generator.
2. **New agent-only components are excluded.** If the pull request adds a component that only makes sense inside the agent (self-monitoring, fleet heartbeats, agent-specific extensions or environment variables, Observe-specific processors), check that `agentOnlyComponents` in `scripts/generate_oss_examples/main.go` excludes it, and that the example still validates with upstream `otelcol-contrib`.
3. **The reference configuration still covers the change.** If the pull request adds a feature that OSS collector users need, such as a new required resource attribute or pipeline, check whether `agent-reference-config.yaml` enables it. If not, ask whether it should.
4. **Behavior is tested.** Changes to how resource attributes such as `deployment.environment.name` are set or ordered must keep `Test_OSSHostExample` passing, and should extend it when they add new behavior.
5. **No credentials.** Examples must read endpoints and tokens from environment variables (`${env:OBSERVE_COLLECTION_URL}`, `${env:OBSERVE_TOKEN}`), never contain a real collection URL or ingest token.
6. **The Kubernetes example may need the same change.** The Kubernetes example lives in `observeinc/helm-charts` under `examples/oss-collector/`. If the change also applies to the Helm chart's collector configuration, mention that the chart and its example need a matching change.
7. **Documentation.** If the change alters what customers must configure (environment variables, required attributes, endpoints), mention that `examples/oss-collector/README.md` and the "Configure your own OTel collector" pages on docs.observeinc.com may need an update.
